* keemacs for emacs

** Introduction

This repository contains two Emacs packages for working with [[https://keepass.info/][KeePass]]
password databases ( =.kdbx= files):

- =keemacs-auth= -- gives Emacs features access to your KeePass
  passwords.  Any Emacs package that fetches credentials through
  =auth-source= (=smtpmail=, =mu4e=, =erc=, =forge=, ...) can read them
  straight out of your KeePass database instead of a flat =.authinfo=
  file.  This package sits underneath things you actually use: it is
  invisible day-to-day, quietly supplying passwords when =auth-source=
  asks for them.  It does nothing interactive -- no browsing, no editing.

- =keemacs= -- an all-singing, all-dancing KeePass browser and
  editor for Emacs.  List entries, search by typing, drill down through
  the folder hierarchy group by group, view an entry with its password
  hidden, copy any field (password, username, URL, notes, TOTP) to the
  clipboard, and add, clone, edit or delete entries directly in the
  database.  It is driven by =consult= and =embark= and is built on top
  of =keemacs-auth=, sharing its command-line backend,
  master-password prompting/caching and error handling.

To choose a package, ask yourself what you want:

| You want...                                               | Use...                   |
|-----------------------------------------------------------+--------------------------|
| Emacs mail/ERC/etc. to log in using your KeePass entries  | =keemacs-auth=    |
| A KeePass client inside Emacs: search, view, copy, edit   | =keemacs=         |

If you just want Emacs packages to use your passwords, only the
=keemacs-auth= section below matters.  If you also want a full
KeePass client inside Emacs, read on to the =keemacs= section.

Both packages talk to a database through one of two command-line
backends:

- =keepassxc-cli=  (default)  [[https://keepassxc.org/][KeePassXC]]'s =keepassxc-cli=, a cross-platform
  client that works on GNU/Linux, macOS and Windows.
- =kpscript=              KeePass's [[https://keepass.info/plugins.html#kpscript][KPScript]], a *Windows-only* scripting
  plugin that drives an installed [[https://keepass.info/][KeePass]].

The backend is chosen automatically by =keemacs-auth-enable=,
preferring =keepassxc-cli= when it is available, and can be forced with
=keemacs-auth-cli=.

** keemacs-auth: credentials for Emacs packages

*** Requirements

No Emacs packages are required (dash.el and s.el are no longer needed).
At least one of the following external programs must be on your
=exec-path=:

- =keepassxc-cli=  (cross-platform; recommended)
- =keepass= and =kpscript=  (Windows-only)

*** Installation

Add =keemacs-auth= to your =load-path=.

*** Setup

1. Add =(require 'keemacs-auth)= to your init file
2. Add =(keemacs-auth-enable)= to your init file to enable using
   KeePass database files as an auth-source
3. Add your database(s) to =auth-sources=

#+BEGIN_SRC elisp
  (require 'keemacs-auth)
  (keemacs-auth-enable)
  (add-to-list 'auth-sources (keepass-make-db-spec :file "~/.emacs.d/passwords.kdbx"))
#+END_SRC

Each =auth-sources= entry is a *database spec*: a keyword plist built
with =keepass-make-db-spec=.  The simplest spec is just a file; add
keywords for a key file, a fixed password, a YubiKey or a passwordless
database.  See [[The database spec]] below.

*** The database spec

Every database used by this package -- in =auth-sources= or in
=keemacs-databases= -- is a keyword spec built with
=keepass-make-db-spec=.

=keepass-make-db-spec= takes keywords and returns a plain plist that the
package reads through accessors like a struct, so the keywords can be
given in any order:

#+BEGIN_SRC elisp
  (keepass-make-db-spec :file   "~/passwords.kdbx")
  ;;                          :keyfile "~/passwords.keyx"
  ;;                          :password "swordfish"   ; or :prompt (default), nil, or a function
  ;;                          :yubi     "1:7370001"
#+END_SRC

The accepted keywords:

| keyword | meaning                                                                     |
|---------+-----------------------------------------------------------------------------|
| =:name= | a short, user-visible label for the database (used by =keemacs=).  Omitted means the file name is used. |
| =:file= | the kdbx file path (string).  The only required keyword.                    |
| =:keyfile= | the key file: a file name, a function returning one, or =nil=.          |
| =:password= | the master password: a string, a function returning one, =:prompt= (ask the user), or =nil= (no master password).  Omitted means =:prompt=. |
| =:yubi= | a YubiKey: a keepassxc-cli =slot[:serial]= string (e.g. ="1:7370001"=), a function returning one, or =nil= for none. |

A keyword value may be a *no-argument function* wherever a string is
allowed (=:keyfile=, =:password=, =:yubi=) -- the function is called each
time the value is needed, so you can fetch a password from a secret store
or decrypt a key file on demand.

For example, a database secured by both a key file and a YubiKey, whose
password you want to be asked for, looks like:

#+BEGIN_SRC elisp
  (keepass-make-db-spec :file "~/work.kdbx"
                        :keyfile "~/work.keyx"
                        :yubi "1:7370001")
#+END_SRC

and a passwordless database is spelled out with an explicit =nil= (note
that omitting =:password= means *ask the user*, not *no password*):

#+BEGIN_SRC elisp
  (keepass-make-db-spec :file "~/public.kdbx" :password nil)
#+END_SRC

Give the spec straight to =auth-source=, either by hand or by listing the
database in =keemacs-databases= (see below):

#+BEGIN_SRC elisp
  (add-to-list 'auth-sources
               (keepass-make-db-spec :file "~/passwords.kdbx"))
#+END_SRC

=keemacs-databases= has a dedicated =M-x customize= interface
(with a =keepass-db-spec= widget) covering both forms.  For =auth-sources=
the plain file-name form is the easy one to customize; keyword specs are
generally set with =setq=, as above.

*** How auth-source finds an entry: the canonical KeePass fields

=auth-source-search= is called by Emacs with a specification of *keys*
like =:host=, =:user=, =:port=, =:title= and so on.  keemacs-auth
maps those onto the **five canonical KeePass entry fields** that
=keepassxc-cli= can actually search:

| Canonical KeePass field | searched by keepassxc-cli as |
|--------------------------|-------------------------------|
| Title                    | =title:=                     |
| UserName                 | =user:=                      |
| Password                 | =password:=                  |
| URL                      | =url:=                       |
| Notes                    | =notes:=                     |

An entry is only found if its canonical field *contains* the value you
are searching for.  For example, searching for =:host "smtp.gmail.com"=
looks in the **URL** field, and searching =:user "you@gmail.com"= looks
in the **UserName** field.

**** Aliases: how the auth-source keys map to the canonical fields

The auth-source keys are aliases for the canonical KeePass fields:

| auth-source key | maps to canonical field | keepassxc-cli term used |
|-----------------|-------------------------|-------------------------|
| =:host=         | URL                     | =url:HOST=             |
| =:user=         | UserName                | =user:USER=            |
| =:title=        | Title                   | =title:TITLE=          |
| =:password=     | Password                | =password:PASSWORD=    |
| =:notes=        | Notes                   | =notes:NOTES=          |

keepassxc-cli's =search= command ANDs together space-separated,
field-scoped terms, so when several keys are present they are combined
into a single query.  For example, searching =:host "smtp.gmail.com"
:user "you@gmail.com" :port 465= runs:

#+BEGIN_SRC text
  keepassxc-cli search <db> url:smtp.gmail.com user:you@gmail.com
#+END_SRC

The port is deliberately left out of the keepassxc-cli term and enforced
by the exact matcher instead: many entries store a bare host or a
=smtp.gmail.com:465=-style URL, and folding the port into the substring
search would exclude them before the matcher ever runs.

Terms match as substrings (no exact-match prefix) so this narrows down to
a small candidate set without assuming the caller passed any particular
combination of keys; the candidate set is then filtered precisely against
every key the caller did pass.  A search may therefore give only
=:host=, only =:user=, host+port, host+user, host+user+port, etc. --
whatever the caller chose to pass is what is matched.

Custom attributes (for example a =host= or =port= *attribute* stored on
an entry) are *not* searchable by keepassxc-cli -- it can only search the
five canonical fields above.  To make a credential findable, store the
server in the URL field and the login in the UserName field.

*** Example: Gmail SMTP with smtpmail

A complete, working outgoing-mail setup:

#+BEGIN_SRC elisp
  (require 'keemacs-auth)
  (keemacs-auth-enable)
  (add-to-list 'auth-sources (keepass-make-db-spec :file "~/.emacs.d/passwords.kdbx"))

  (setq send-mail-function        'smtpmail-send-it
        message-send-mail-function 'smtpmail-send-it
        smtpmail-smtp-server  "smtp.gmail.com"
        smtpmail-smtp-service 465
        smtpmail-stream-type  'ssl
        smtpmail-smtp-user    "you@gmail.com"
        user-mail-address     "you@gmail.com")
#+END_SRC

The matching KeePass entry must have its **URL** field set to
=smtp.gmail.com:465= and its **UserName** field set to
=you@gmail.com=.  (If you omit the port from the search, the URL can just
be =smtp.gmail.com=.)

Note that Gmail requires an [app
password](https://support.google.com/accounts/answer/185833), not your
account password.

*** Configuration

**** Choosing a backend

By default the backend is auto-detected.  To force one:

#+BEGIN_SRC elisp
  (setq keemacs-auth-cli 'keepassxc) ; keepassxc-cli (default, cross-platform)
  (setq keemacs-auth-cli 'kpscript)  ; KeePass KPScript (Windows)
#+END_SRC

The paths to each external program can also be customized:

- =keemacs-auth-keepassxc-cli-program= (default =keepassxc-cli=)
- =keemacs-auth-keepass-program=      (default =keepass=)
- =keemacs-auth-kpscript-program=       (default =kpscript=)

All of these are =defcustom=s and can be customized via
=M-x customize-variable=.

**** Master-password cache expiry

KeePass database passwords are set to expire after two hours.  This can
be customized by setting =keemacs-auth-cache-expiry= to any other
value.  Set it to =nil= to never expire (the master password is then
cached for the rest of the Emacs session):

#+BEGIN_SRC elisp
  (setq keemacs-auth-cache-expiry nil) ; never expire
  (setq keemacs-auth-cache-expiry 86400) ; one day
#+END_SRC

This controls how often you are re-prompted for the KeePass database
master password.  Even with =nil=, you can force a re-prompt with
<kbd>M-x</kbd> =keemacs-auth-forget-cached=.

**** Verbose logging

To see every =keepassxc-cli= command the backend runs (useful for
debugging why a lookup narrows the way it does):

#+BEGIN_SRC elisp
  (setq keemacs-auth-verbose t)
#+END_SRC

Each invocation is logged to a =*keemacs-auth-log*= buffer.

It is normal for a single action (such as sending mail) to trigger
*several* auth-source lookups, and therefore several =keepassxc-cli=
commands.  Emacs's TLS layer and application layers issue separate
searches with different specs.  For smtpmail specifically you will often
see two:
  1. a host+port-only search (no user), driven by
     =network-stream-certificate= looking up a TLS certificate for
     =host:port=, and
  2. the actual credential search with host + user + port.

Both are legitimate; neither indicates a bug.

**** Suppressing negative caching

=auth-source= normally remembers every search result -- including an
empty one -- for =auth-source-cache-expiry= seconds.  A single failure
(the database is locked, the password was wrong, =keepassxc-cli= was
momentarily unavailable) therefore keeps every later lookup returning nil
long after the cause is gone.

By default keemacs-auth installs advice so that empty results are
never cached, so a miss does not stick:

#+BEGIN_SRC elisp
  (setq keemacs-auth-suppress-negative-cache t) ; the default
#+END_SRC

*** Clearing the cache

If you change your KeePass database, change an entry, or re-configure,
a stale cached value can mask the change.  Run:

- <kbd>M-x</kbd> =keemacs-auth-forget-cached= -- forgets the cached
  KeePass *master password*, so the next lookup re-prompts for it.  This
  only touches keemacs-auth's own cache.
- <kbd>M-x</kbd> =auth-source-forget-all-cached= -- clears the
  =auth-source= search-result cache.  (This is called automatically by
  =keemacs-auth-enable=; use it if a *found* result is stale.)

** keemacs: a KeePass client inside Emacs

=keemacs= lists the entries of a KeePass database, lets you pick
one by typing, views it with the password hidden, and acts on it: copy
any field to the clipboard, insert into the current buffer, or add,
clone, edit and delete entries.  It uses =consult= (works with =vertico=)
for selection and =embark= for the action menu, so if you already live in
that ecosystem it fits right in.

It deliberately reuses everything from =keemacs-auth=: the same
=keepassxc-cli= execution, the same master-password prompting/caching,
and the same database specification.

*** Requirements

- =keemacs-auth= (in this repository)
- =consult=, =embark= and =embark-consult= -- installable from [[https://melpa.org/][MELPA]]
  (embark-consult provides preview in the selection minibuffer)
- =keepassxc-cli= on your =exec-path= (the browse features are built
  around =keepassxc-cli=; the kpscript backend is not used for browsing)

*** Installation

Add both files to your =load-path= and require =keemacs=:

#+BEGIN_SRC elisp
  (require 'keemacs)
#+END_SRC

=keemacs= requires =keemacs-auth= and pulls it in.

*** Setup: tell it about your databases

The one thing this package adds on top of =keemacs-auth= is
=keemacs-databases=: a *list* of database spec plists (see
[[The database spec]] above), each with an optional =:name= label that
defaults to the file name.  A config is just a quoted list of plists:

#+BEGIN_SRC elisp
  (setq keemacs-databases
        '((:name "personal" :file "~/Google/AppData/KeePass/KeePassDB2.kdbx")
          (:name "work"     :file "~/Google/AppData/KeePass/KeePassDB3.kdbx"
                 :keyfile "~/work.keyx"
                 :yubi "1:7370001")))
#+END_SRC

Since every entry is a plist, a plain quoted list works for most setups.
If a value is a function (e.g. a =:password= that fetches from a secret
store), build the list with =list= and =keepass-make-db-spec= instead, so
the call is evaluated.

With several databases configured, the first command you run asks which
one to use (=keemacs-select-database=); with exactly one it is
selected automatically.  You can switch at any time with <kbd>M-x</kbd>
=keemacs-select-database=.

*** Using keemacs

Three entry points:

- <kbd>M-x</kbd> =keemacs= -- select an entry through the
  minibuffer (consult/vertico completion; typing narrows).  RET runs the
  default action (=keemacs-default-action=, by default *view*);
  <kbd>C-.</kbd> opens the full action menu.

- <kbd>M-x</kbd> =keemacs-buffer= -- a columned listing buffer of
  every entry; move to a row and press <kbd>C-.</kbd> (=embark-act=) for
  the action menu.

- <kbd>M-x</kbd> =keemacs-group= -- the same completion but
  *group by group*: it starts at the database root (=/=) and completes
  over the current group's subgroups and entries, so you drill down a
  KeePass folder hierarchy one level at a time (=/=, then =Internet/=,
  then =Google/=, then the entry you want) instead of narrowing a flat
  list.  Choosing a subgroup descends; choosing an entry runs the same
  =keemacs-default-action= as =keemacs=.  Group lines show
  the group's icon (thumbnails for imported images, glyphs for the
  standard set), and empty groups are listed too.

From any of these, the entry actions are:

Each entry is prefixed with its icon: on a graphic display an entry with
a custom icon shows the actual image (a small thumbnail in the picker, a
larger one at the top of the view buffer); otherwise a unicode glyph
approximates the entry's standard KeePass icon (key, globe, envelope,
camera, ...).

| key   | action                                |
|-------+---------------------------------------|
| =t=   | copy title                            |
| =u=   | copy username                         |
| =p=   | copy password                         |
| =l=   | copy URL                              |
| =n=   | copy notes                            |
| =o=   | copy the current TOTP (if the entry has one) |
| =v=   | view the entry (hide/show password)   |
| =e=   | edit the entry                        |
| =c=   | clone the entry                       |
| =a=   | add a new entry in this group         |
| =d=   | delete the entry                      |

The selection minibuffer additionally offers =insert username= (=[P]=)
and =insert password= (=[U]=) at point, and the =keemacs-insert-password=
and =keemacs-insert-username= commands are available directly if
you want to insert a password into your current buffer.

**** Binding all the commands at once

=keemacs-command-map= is a sparse keymap holding every command of
this package, so one line binds them all:

#+BEGIN_SRC elisp
  (keymap-global-set "C-:" 'keemacs-command-map)
#+END_SRC

The default bindings under the prefix (=C-:= here, any prefix you like):

| key   | command                             |
|-------+-------------------------------------|
| =t=   | =keemacs=                    |
| =g=   | =keemacs-group=              |
| =d=   | =keemacs-select-database=    |
| =f=   | =keemacs-favorites=          |
| =k=   | =keemacs-favorites-embark=   |
| =c=   | =keemacs-auth-forget-cached= |
| =a=   | =keemacs-add=                |

On Emacs versions without =keymap-global-set= (pre-29), the classic
spelling is:
#+BEGIN_SRC elisp
  (global-set-key (kbd "C-:") 'keemacs-command-map)
#+END_SRC

The map is autoloaded, so the binding works even before the package is
loaded.  Any prefix key works -- bind =F5= or =C-c k= the same way.

**** The entry view

=keemacs-view= shows an entry with its password hidden:

#+BEGIN_SRC text
  Group      /Internet/Google/
  Title      My server
  UserName   alice
  Password   [hidden - press r]
  URL        https://example.com
  Notes      ...

  [t] copy title     [c] clone
  [u] copy username  [a] add
  ...
#+END_SRC

Press =r= to reveal or re-hide the password; =u=, =p=, =l=, =n=, =o= copy
the corresponding field; =e= edits; =q= quits.  The key menu at the
bottom shows all the bindings.

**** Editing

Add, clone, edit and delete are all done through =keepassxc-cli= write
commands and take effect directly in the database:

- *edit* is performed in place (the title may be changed without turning
  the entry into a delete+add), so you never end up with Recycle-Bin
  duplicates;
- *move* is part of editing: the edit buffer opens with a =Group: =
  line above the =Title =.  Editing =Group= to a different group moves
  the entry there (and keeps any Title change at the same time) via
  =keepassxc-cli mv=, so it still is never a delete+add;
- *choosing a group* -- typing a group path by hand is error-prone, so
  =C-c C-p= in the entry buffer completes over the groups that already
  exist and fills in the =Group: = line for you.  Every entry buffer opens
  with a =;; Keys:= hint line showing the keybindings (=C-c C-c= commit,
  =C-c C-p= select group, =C-c C-r= regenerate, =C-c C-k= cancel), and
  <kbd>C-h m</kbd> lists them too;
- *regenerate a password* -- =C-c C-r= asks which generation option to
  use (completing over the labels of `keemacs-generate-options`,
  e.g. ="upper case"=, ="with numeric"=, ="all printable (!-~)"=,
  ="passphrase"=) and a length, then runs keepassxc-cli and fills the
  =Password = line.  The last choices are remembered as defaults.  The
  options are fully customizable -- each is (LABEL ARGS), where ARGS is
  the *whole* keepassxc-cli command (subcommand plus flags) with the
  symbol =:length= standing in for the requested length:
  #+BEGIN_SRC elisp
    (setq keemacs-generate-options
          '(("upper case"     ("generate" "--upper" "--length" :length))
            ("lower case"     ("generate" "--lower" "--length" :length))
            ("mixed case"     ("generate" "--lower" "--upper" "--length" :length))
            ("with numeric"   ("generate" "--lower" "--upper" "--numeric" "--length" :length))
            ("all printable (!-~)"
             ("generate" "--custom"
              "!\"#$%&'()*+,-./0123456789:;<=>?@ABCDEFGHIJKLMNOPQRSTUVWXYZ[\\]^_`abcdefghijklmnopqrstuvwxyz{|}~"
              "--length" :length))
            ("passphrase"     ("diceware" "--words" :length))))
  #+END_SRC
  =generate= takes =--length=; the diceware =passphrase= takes
  =--words=.  Add, remove or reorder entries to taste.
- *add* -- called directly (=M-x keemacs-add= or =C-: a=), it asks
  which group to create the entry in (completion over existing groups;
  =RET= alone picks the root, creating a top-level entry), then opens the
  entry buffer.  Called as an Embark action on a selected entry (=a= in
  the action menu), it skips the question and adds to that entry's
  group;
- *delete* asks for confirmation and moves the entry to the Recycle Bin
  (the browse buffer excludes the Recycle Bin, so the entry disappears
  from the listing).

Every listing is read fresh from the database -- nothing is held in a
cache -- so a change you make in keemacs shows up on the next
listing (press =g= in the browse buffer, or just select again with
=keemacs=, which always reads the database anew).  Changes made
elsewhere (e.g. KeePassXC's GUI or a sync) are picked up the same way.

**** Clipboard clearing

=keemacs-clear-clipboard-seconds= (default 0, meaning off) clears
the clipboard that many seconds after a copy, and only if the clipboard
still holds the value you copied -- so it never wipes over what you paste
in the meantime.

**** Customization

- =keemacs-fields= -- which canonical fields are shown in each
  candidate line and in what order (default =("Title" "UserName" "URL")=).
- =keemacs-field-width= -- width each field is clipped to in the
  candidate lines (default 24).  Raise it if long titles -- e.g. ones
  containing =/= -- are hard to tell apart.
- =keemacs-default-action= -- what RET does after
  =keemacs= selects an entry (default =keemacs-view=).
- =keemacs-cache-expiry= -- master-password expiry for browsing
  (default 7200 seconds; =nil= to never expire).
- =keemacs-clear-clipboard-seconds= -- see above.

All are =defcustom=s, adjustable with <kbd>M-x</kbd>
=customize-variable= or <kbd>M-x</kbd> =customize-group= =keemacs=.

*** Sharing databases with auth-source

The browse list is already a list of database spec plists, so telling
=auth-source= about your browsing databases (so email/ERC/etc. can use
them too) is just an append:

#+BEGIN_SRC elisp
  (setq auth-sources (append auth-sources keemacs-databases))
#+END_SRC

** Tests

An ERT test suite lives in =test/=.

- =test/keemacs-auth-test.el= covers the auth-source package:
  parsing, term building, the host/user/port matcher, spec normalization,
  negative-cache suppression -- plus integration tests that build a
  throwaway KeePassXC database and search it for real.
- =test/keemacs-test.el= covers browsing: parsing, field
  extraction, and copy/edit/delete against a throwaway database.

Run the auth-source suite with:

#+BEGIN_SRC sh
  emacs -Q --batch -L . -l ert -l keemacs-auth.el \
        -l test/keemacs-auth-test.el -f ert-run-tests-batch-and-exit
#+END_SRC

and the browse suite with:

#+BEGIN_SRC sh
  emacs -Q --batch -L . -l ert -l keemacs.el \
        -l test/keemacs-test.el -f ert-run-tests-batch-and-exit
#+END_SRC

The integration tests (and the browse suite generally) require
=keepassxc-cli= on =exec-path=; they are skipped wholesale when it is
missing, so both suites are safe to run on machines without KeePassXC.

The browse suite also needs =consult=, =embark= and =embark-consult=
findable (add their =elpa/= directories to =load-path=, as with a normal
install), since =keemacs= requires them.
